# Установка HTTP-сервиса REO (шаблоны reo_statement и reo_contracts)

Версия: v1.0 · Дата: 2026-10-28
Дополняет: «Получение данных из 1С по HTTP.md» (Части 1–7). Общие правила (тестовая копия, публикация, проверка по IP) — там же.

---

## 1. Что добавляем

Два шаблона URL в **существующий** HTTP-сервис `DemoApi` (корневой URL `demo-api`), рядом с `osv_60_02`:

| Шаблон URL | Метод | Обработчик | Назначение |
|---|---|---|---|
| `reo_statement` | GET | `reo_statementGET` | Построчные учётные записи: платежи (advance/works/cession), зачёты авансов, реализации |
| `reo_contracts` | GET | `reo_contractsGET` | Справочник договоров: Договор, ВидДоговора, Контрагент, ИНН, НоменклатурнаяГруппа |

Итоговые URL (после публикации):

```
http://<IP_сервера_1С>/<публикация>/hs/demo-api/reo_statement?date_from=ГГГГ-ММ-ДД&date_to=ГГГГ-ММ-ДД
http://<IP_сервера_1С>/<публикация>/hs/demo-api/reo_contracts[?ng=...&counterparty=...&contract=...]
```

## 2. Подготовка

1. Работать **только на тестовой копии** базы (Часть 1.1 инструкции-источника).
2. Закрыть все сессии 1С:Предприятие перед работой в Конфигураторе.
3. Убедиться, что в модуле сервиса `DemoApi` уже есть функция `СформироватьОтвет` (появилась при создании `osv_60_02`). **Второй раз её не вставлять** — будет ошибка компиляции «двойное определение».

## 3. Добавление шаблонов и кода

Для каждого из двух шаблонов:

1. Конфигуратор → `HTTP-сервисы` → `DemoApi` → `Шаблоны URL` → правая кнопка → `Добавить`:
   - Имя: `reo_statement` (затем повторить для `reo_contracts`)
   - Шаблон URL: `reo_statement` (плоский, как `osv_60_02`)
2. Раскрыть шаблон → `Добавить метод` → GET.
3. В поле «Обработчик» указать имя функции: `reo_statementGET` (соответственно `reo_contractsGET`).
4. Открыть редактор модуля и вставить содержимое соответствующего файла:
   - `1c/reo_statement.bsl` → модуль шаблона `reo_statement`
   - `1c/reo_contracts.bsl` → модуль шаблона `reo_contracts`
5. В модуль шаблона `reo_statement` входят также функции `РазобратьДатуISO` и `ПодходитПодФильтр`. Если `ПодходитПодФильтр` уже добавлялась ранее — оставить одну копию.

**Важно:** в 1С модуль HTTP-сервиса — общий для всех шаблонов сервиса. Функции из разных файлов вставляются в ОДИН модуль; следите, чтобы имена функций не дублировались.

6. `Синтаксический контроль` (Ctrl+F7), затем сохранить (Ctrl+S).

## 4. Проверка прав (служебный пользователь)

1. Создать пользователя `REO_CLIENT` (Администрирование → Пользователи), аутентификация 1С, пароль.
2. Создать роль `REO_WebAccess` и назначить пользователю:
   - право **«Использование»** на HTTP-сервис `DemoApi` (ветка «HTTP-сервисы» в дереве прав);
   - **«Чтение»** на: регистр бухгалтерии `Хозрасчетный`, справочники `Контрагенты`, `ДоговорыКонтрагентов`, `НоменклатурныеГруппы`.
3. Никаких других прав (запись, документы) — не давать.

## 5. Публикация и проверка

Если база уже опубликована на IIS (как для `osv_60_02`) — переопубликовать не нужно, шаблоны подхватятся автоматически. Иначе — Часть 5 инструкции-источника (Конфигуратор от администратора, галочка «Публиковать HTTP-сервисы»).

Проверка в браузере **по IP сервера 1С** (не localhost):

```
http://<IP>/demo_demo-api/hs/demo-api/reo_contracts?counterparty=ИнвестСтрой
http://<IP>/demo_demo-api/hs/demo-api/reo_statement?date_from=2025-01-01&date_to=2025-01-31
```

Ожидаемые коды ответов — как у `osv_60_02`:

| Код | Причина |
|---|---|
| 200 | JSON-массив записей |
| 400 | не переданы/неверны даты; период > 366 дней; date_to < date_from |
| 401 | неверный логин/пароль |
| 404 | публикация/URL |
| 500 | ошибка запроса — смотреть текст ошибки и журнал регистрации |

## 6. Приёмка: сверка с ОСВ (обязательный этап)

Сверить за тестовый период (например, месяц):

| Проверка | Как сверить |
|---|---|
| `advance` | ОСВ по 62.02, обороты Кт в корреспонденции с 51/52 |
| `works` | ОСВ по 62.01, обороты Кт в корреспонденции с 51/52 |
| `cession` | ОСВ по 62.02, обороты Кт в корреспонденции с 76.** и 60.01 |
| `closed_advance` | ОСВ по 62.02, обороты Кт в корреспонденции с 62.01 |
| `realization` | ОСВ по 90.01.1, разрез БУ (с НДС) = обороты Дт 62.0x |
| `needs_review` | строки с пустым Договором/Контрагентом — проверить вручную в 1С |

Контрольная точка: сумма всех `realization` по договору за период = оборот Дт 62.0x/Кт 90.01.1 (БУ) по этому договору.

## 7. Типичные ошибки именно этого сервиса

| Ошибка | Причина | Решение |
|---|---|---|
| «Поле не найдено: НоменклатурнаяГруппа» | реквизит договора называется иначе в вашей редакции | Конфигуратор → Справочники → ДоговорыКонтрагентов → Реквизиты; поправить имя в обоих файлах |
| «Поле не найдено: ВидДоговора» | аналогично | проверить имя реквизита/перечисления |
| «Поле не найдено: ЭтоГруппа» | справочник договоров не иерархический | убрать строку `И НЕ Договоры.ЭтоГруппа` из `reo_contracts.bsl` |
| «Функция уже определена: СформироватьОтвет» | вставили второй раз | удалить дубль, оставить существующую |
| Пустой `НоменклатурнаяГруппа` у записей | у договора не заполнена НГ | заполнить в 1С или маппить вручную на портале |
| `needs_review: true` у записей | пустые субконто (обычно ручные операции) | проверить документ в 1С; записи не теряются |

## 8. Контракт ответа `reo_statement` (для портала)

```json
[
  {
    "record_type": "payment",            // payment | closed_advance | realization
    "payment_type": "advance",           // advance | works | cession (только payment)
    "Контрагент": "ИнвестСтрой",
    "ИНН": "...",
    "Договор": "дог.№103 от 02.03.23 и /д/с№15 корпус 2 Этап 2 ...",
    "ВидДоговора": "С покупателем",
    "НоменклатурнаяГруппа": "регион стройка корпус 2 северный дог.103",
    "Дата": "2025-03-14",                // период проводки
    "ДокументНомер": "00БП-000385",
    "ДокументДата": "2025-03-14",
    "ДокументРасчетов": "Поступление на расчетный счет 00БП-000385 от 14.03.2025",
    "ДоговорКт": "",                     // заполняется только у closed_advance (контроль)
    "Сумма": 76500,
    "needs_review": false
  }
]
```

Примечания:
- `Сумма` у `realization` — с НДС (Сумма Дт); сторно реализации приходит с минусом.
- `ДокументРасчетов` может быть пустой строкой (цессии) — счета учета при этом всегда определены.
- Ручные операции включаются автоматически (отбор по корреспонденции, без фильтра по регистратору).
